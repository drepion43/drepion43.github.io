## MCP란 무엇인가

Claude Code는 기본적으로 로컬 파일 시스템과 터미널에만 접근할 수 있습니다. 코드를 읽고 고치고 명령을 실행하는 것까지는 되지만, "이 Jira 이슈를 열어줘", "Slack에 메시지를 보내줘", "우리 프로덕션 DB에서 최근 가입자를 조회해줘" 같은 요청은 원래대로라면 처리할 방법이 없습니다.

**MCP(Model Context Protocol)** 는 이 경계를 확장하는 오픈 표준입니다. AI 에이전트가 외부 서비스(데이터베이스, 이슈 트래커, 모니터링 도구, SaaS API 등)와 통신할 때 쓰는 공통 프로토콜이라고 생각하면 됩니다. MCP 서버 하나를 Claude Code에 연결하면, 그 서버가 노출하는 도구(tool)들이 마치 `Read`, `Bash` 같은 Claude Code 내장 도구인 것처럼 모델에게 제공됩니다.

### 왜 "표준"이 필요한가

MCP가 없다면 "Claude Code를 Jira에 연동한다", "Claude Code를 Slack에 연동한다" 같은 통합을 서비스마다 각각 다른 방식으로 만들어야 합니다. MCP는 이 연동 방식을 하나의 프로토콜로 통일해서, 서버를 만드는 쪽(Jira, Slack, 사내 DB 등)과 서버를 사용하는 쪽(Claude Code, 다른 AI 클라이언트)이 서로 신경 쓸 필요 없이 맞물리게 해줍니다. 그래서 한 번 만들어진 MCP 서버는 Claude Code뿐 아니라 이 표준을 지원하는 다른 AI 도구에서도 그대로 재사용할 수 있습니다.

### MCP로 할 수 있는 것

몇 가지 예를 들면 다음과 같습니다.

- **이슈 트래커 연동**: "이슈 트래커의 ENG-4521 티켓 내용대로 기능을 구현하고 PR을 만들어줘"
- **모니터링 조회**: "에러 모니터링 서비스에서 최근 24시간 동안 발생한 에러를 확인해줘"
- **데이터베이스 조회**: "운영 DB에서 최근 가입한 사용자 10명을 찾아줘"
- **업무 자동화**: "메일 초안을 작성해줘"
- **외부 이벤트 수신**: MCP 서버가 채팅 메신저의 새 메시지나 웹훅 이벤트를 세션으로 직접 밀어넣는 것도 가능

즉 MCP는 Claude Code에 "외부 도구를 쓸 수 있는 손"을 붙여주는 역할을 합니다.

## MCP 서버의 통신 방식

MCP 서버는 통신 방식(트랜스포트)에 따라 몇 가지로 나뉩니다. 서버를 추가할 때 이 중 하나를 선택합니다.

| 방식 | 특징 | 주로 쓰이는 경우 |
|---|---|---|
| **HTTP** (권장) | 원격 서버와 표준 HTTP로 통신 | 대부분의 클라우드 SaaS MCP 서버 |
| **SSE** (레거시) | Server-Sent Events 방식, HTTP 이전 세대 | 과거에 만들어진 서버와의 호환 유지 |
| **Stdio** | 로컬에서 프로세스를 직접 실행하고 표준 입출력으로 통신 | `npx`로 실행하는 패키지, 직접 만든 로컬 서버 |
| **WebSocket** | 지속적인 양방향 연결 | 서버가 요청 없이도 이벤트를 먼저 밀어넣어야 하는 경우 |

클라우드 서비스에 붙는 경우는 대부분 HTTP, 로컬 프로세스를 직접 띄우는 경우는 Stdio라고 이해하면 실무에서는 거의 충분합니다.

## Claude Code CLI에서 MCP 사용법

### 1. 서버 추가

기본 명령어는 `claude mcp add`입니다.

```bash
# HTTP 서버 추가
claude mcp add --transport http notion https://mcp.notion.com/mcp

# 인증 헤더가 필요한 경우
claude mcp add --transport http internal-api https://api.company.com/mcp \
  --header "Authorization: Bearer your-token"

# Stdio 서버 추가 (로컬 프로세스 실행)
claude mcp add --transport stdio filesystem \
  -- npx -y @modelcontextprotocol/server-filesystem /path/to/project
```

Stdio 서버는 `--` 뒤에 실제로 실행할 명령어와 인자를 그대로 적습니다. `--`가 없으면 Claude Code가 서버의 옵션(예: `--port`)을 자신의 옵션으로 잘못 해석할 수 있으니 주의해야 합니다.

JSON으로 한 번에 추가할 수도 있습니다.

```bash
claude mcp add-json weather-api '{"type":"http","url":"https://api.weather.com/mcp"}'
```

### 2. 서버 관리

```bash
# 등록된 서버 목록 확인 (연결 상태도 함께 표시)
claude mcp list

# 특정 서버 상세 정보
claude mcp get notion

# 서버 제거
claude mcp remove notion

# 세션 안에서 서버 상태 확인/관리
/mcp
```

`claude mcp list`를 실행하면 서버 이름 옆에 `✔ Connected`(연결됨), `! Needs authentication`(인증 필요), `✘ Failed to connect`(연결 실패) 같은 헬스 상태가 함께 표시됩니다. 설정을 지우지 않고 잠깐 끄고 싶을 때는 `/mcp` 패널에서 서버를 토글로 비활성화할 수 있습니다.

### 3. 스코프 — 어디까지 이 서버를 쓸 것인가

MCP 서버를 어느 범위에 등록하느냐에 따라 다른 프로젝트에서도 보이는지, 팀과 공유되는지가 달라집니다.

| 스코프 | 로드 범위 | 팀 공유 | 저장 위치 |
|---|---|---|---|
| `local` (기본) | 현재 프로젝트만 | 아니오 | `~/.claude.json` |
| `project` | 현재 프로젝트만 | 예 (버전 관리) | 프로젝트 루트의 `.mcp.json` |
| `user` | 모든 프로젝트 | 아니오 | `~/.claude.json` |

```bash
# 개인 실험용 서버 (기본값, local)
claude mcp add --transport http stripe https://mcp.stripe.com

# 팀 전체가 공유하는 서버 — .mcp.json에 기록되어 커밋 가능
claude mcp add --transport http shared-server --scope project https://example.com/mcp

# 모든 프로젝트에서 공통으로 쓰는 개인 유틸리티
claude mcp add --transport http hubspot --scope user https://mcp.hubspot.com/anthropic
```

팀 전체가 같은 이슈 트래커나 사내 DB 서버를 쓰는 상황이라면 `--scope project`로 등록해서 `.mcp.json`을 저장소에 커밋하는 것이 좋습니다. 반대로 개인 API 키가 들어가는 실험적인 서버는 기본값인 `local` 스코프로 두는 편이 안전합니다.

### 4. 인증(OAuth)

클라우드 MCP 서버 상당수는 로그인이 필요합니다. Claude Code는 OAuth 2.0 플로우를 내장하고 있어서, 브라우저 로그인 한 번이면 토큰이 저장되고 이후로는 자동 갱신됩니다.

```bash
# 1. 서버 추가
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

# 2. 세션 안에서 인증
/mcp
# → 브라우저가 열리며 로그인 절차 진행
```

셸에서 바로 로그인/로그아웃하고 싶다면 다음 명령어를 쓸 수 있습니다.

```bash
claude mcp login sentry
claude mcp logout sentry
```

### 5. 설정 파일에 시크릿을 직접 적지 않기

`.mcp.json`은 팀과 공유하거나 버전 관리에 커밋되는 경우가 많으므로, API 키를 그대로 적어두면 안 됩니다. 대신 환경 변수 치환 문법을 씁니다.

```json
{
  "mcpServers": {
    "internal-api": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": {
        "Authorization": "Bearer ${API_KEY}"
      }
    }
  }
}
```

`${VAR}`는 환경 변수 `VAR`의 값으로, `${VAR:-default}`는 `VAR`가 없을 때 기본값으로 치환됩니다. 이렇게 하면 실제 키 값은 각자의 로컬 환경 변수에만 존재하고, 저장소에는 참조만 남습니다.

## MCP가 제공하는 도구 외 기능: 프롬프트와 리소스

MCP 서버는 단순히 "도구(함수)"만 제공하는 게 아니라, 두 가지를 더 노출할 수 있습니다.

- **프롬프트(Prompt)**: 특정 작업 흐름을 시작하는 대화 템플릿입니다. `/mcp__서버이름__프롬프트이름` 형식의 슬래시 명령어로 호출합니다.

  ```bash
  /mcp__github__pr_review 456
  /mcp__jira__create_issue "로그인 화면 버그" high
  ```

- **리소스(Resource)**: 서버가 노출하는 읽기 전용 데이터입니다. DB 스키마나 이슈 상세 내용처럼, 도구를 호출하지 않고도 `@` 멘션으로 바로 대화에 첨부할 수 있습니다.

  ```
  @github:issue://123 을 분석하고 수정 방법을 제안해줘
  ```

도구가 "실행 가능한 동작"이라면, 프롬프트는 "미리 정해둔 작업 시작점", 리소스는 "참조 가능한 데이터"라고 구분하면 이해하기 쉽습니다.

## 컨텍스트를 지키기 위한 장치들

MCP 서버를 여러 개 연결하면 도구 정의만으로도 컨텍스트 윈도우가 금방 찰 수 있습니다. 이를 위해 Claude Code는 두 가지 장치를 둡니다.

- **Tool Search(지연 로딩)**: 기본적으로 MCP 도구의 이름과 서버 설명만 가볍게 로드해두고, 실제로 그 도구가 필요하다고 판단될 때만 전체 스키마를 불러옵니다. 서버를 몇 개를 연결하든 평소 컨텍스트 사용량에는 큰 영향이 없는 구조입니다.
- **출력 토큰 제한**: MCP 도구가 반환하는 결과가 너무 크면(기본 25,000 토큰 초과 시) 잘라냅니다. DB에서 대량의 레코드를 조회하는 것처럼 큰 출력이 정말 필요한 경우에는 `MAX_MCP_OUTPUT_TOKENS` 환경 변수로 상한을 늘릴 수 있습니다.

## 자주 쓰이는 MCP 서버 예시

MCP 생태계에는 이미 다양한 서버가 공개되어 있습니다. 실무에서 자주 연동되는 몇 가지 카테고리를 예로 들면 다음과 같습니다.

| 카테고리 | 예시 서버 | 주요 용도 |
|---|---|---|
| 코드 협업 | GitHub, GitLab | PR/이슈 조회 및 생성, 코드 리뷰 코멘트 확인 |
| 이슈 트래커 | Jira, Linear, Asana | 티켓 조회, 이슈 생성/업데이트 |
| 데이터베이스 | PostgreSQL, SQLite | 스키마 확인, 쿼리 실행 |
| 파일/문서 | 로컬 Filesystem, Notion | 로컬 디렉터리 접근, 문서 페이지 조회/수정 |
| 커뮤니케이션 | Slack | 채널 메시지 조회, 알림 전송 |
| 모니터링 | Sentry | 에러/이슈 조회 |
| 결제 | Stripe | 결제/고객 데이터 조회 |
| 브라우저 자동화 | Puppeteer, Playwright 계열 | 웹 페이지 조작 및 스크린샷 |
| 웹 검색 | Brave Search 등 | 실시간 웹 검색 결과 조회 |

예를 들어 백엔드 개발자라면 `postgres`(로컬 개발 DB 스키마 확인), `github`(PR 자동 생성), `sentry`(배포 후 에러 확인) 세 가지 조합만으로도 "에러 로그 보고 → 원인 되는 쿼리 확인 → 코드 수정 → PR 생성"까지 한 세션 안에서 처리하는 흐름을 만들 수 있습니다. 어떤 서버가 필요한지는 결국 팀이 이미 쓰고 있는 서비스가 무엇인지에 달려 있으므로, 위 목록은 "이런 게 있다"는 감을 잡는 용도로 참고하면 됩니다.

### CLI로 실제로 추가하는 방법

위 서버들은 트랜스포트 방식이 서로 다릅니다. 클라우드에 이미 호스팅되어 있는 서비스는 HTTP로, 로컬 프로세스로 직접 띄워야 하는 서버는 Stdio로 추가합니다.

**HTTP 방식 (클라우드 호스팅 서버)** — URL만 알면 바로 등록됩니다.

```bash
# Notion
claude mcp add --transport http notion https://mcp.notion.com/mcp

# Slack
claude mcp add --transport http slack https://mcp.slack.com/mcp

# Sentry
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

# Stripe
claude mcp add --transport http stripe https://mcp.stripe.com
```

등록 후 인증이 필요한 서버라면 세션 안에서 `/mcp`를 실행해 브라우저 로그인을 한 번 거치면 됩니다.

**Stdio 방식 (로컬 프로세스로 실행)** — `npx`로 패키지를 그 자리에서 실행하는 경우가 많습니다.

```bash
# 로컬 파일 시스템 접근
claude mcp add --transport stdio filesystem \
  -- npx -y @modelcontextprotocol/server-filesystem /path/to/project

# GitHub (개인 액세스 토큰 필요)
claude mcp add --env GITHUB_PERSONAL_ACCESS_TOKEN=YOUR_TOKEN --transport stdio github \
  -- npx -y @modelcontextprotocol/server-github

# PostgreSQL (연결 문자열을 인자로 전달)
claude mcp add --transport stdio postgres \
  -- npx -y @modelcontextprotocol/server-postgres postgresql://user:pass@localhost/dbname

# 브라우저 자동화(Puppeteer)
claude mcp add --transport stdio puppeteer \
  -- npx -y @modelcontextprotocol/server-puppeteer
```

Stdio 서버는 `--env KEY=value`로 API 키나 토큰을 환경 변수로 전달하고, `--` 뒤에는 실제로 실행할 명령어와 인자를 그대로 적습니다. 팀 전체가 공유해야 하는 서버라면 여기에 `--scope project`를 추가해 `.mcp.json`에 기록하고 저장소에 커밋하면 됩니다.

## 정리

MCP는 Claude Code가 로컬 파일 시스템·터미널이라는 경계를 넘어 외부 서비스와 통신할 수 있게 해주는 오픈 표준입니다. `claude mcp add`로 서버를 등록하고, `local`/`project`/`user` 스코프로 공유 범위를 정하고, 필요하면 OAuth로 인증하는 것이 기본 사용 흐름입니다. 도구(tool) 외에도 슬래시 명령어로 호출하는 프롬프트, `@` 멘션으로 참조하는 리소스까지 함께 제공된다는 점도 알아두면 좋습니다. 서버를 여러 개 연결해도 Tool Search 덕분에 평소 컨텍스트 사용량은 크게 늘지 않으므로, 팀에서 이미 쓰고 있는 이슈 트래커·DB·모니터링 서비스가 MCP 서버로 제공된다면 하나씩 연결해보는 것이 Claude Code 활용도를 크게 높이는 방법입니다.
