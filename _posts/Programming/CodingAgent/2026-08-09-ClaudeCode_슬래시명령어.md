## 들어가며

앞서 <a href="https://drepion43.github.io/codingagent/ClaudeCode_기능/" target="_blank">기본/커스텀 커맨드</a>, <a href="https://drepion43.github.io/codingagent/ClaudeMd_파일기능/" target="_blank">CLAUDE.md</a>, <a href="https://drepion43.github.io/codingagent/ClaudeCode_Skills/" target="_blank">Skills</a>를 다뤘습니다. 이 글에서는 그중 "기본 커맨드"에 해당하는 내장 슬래시 명령어들을 좀 더 자세히 정리하겠습니다. 인터랙티브 세션에서 `/`를 입력하면 목록이 뜨고, 글자를 이어 입력하면 필터링됩니다. 커스텀 커맨드가 사용자가 직접 만든 단축 프롬프트라면, 여기서 다루는 명령어들은 Claude Code가 기본으로 제공하는 조작 도구들입니다.

명령어 수가 많기 때문에 전부 외울 필요는 없습니다. 이 글에서는 "어떤 상황에서 어떤 명령어를 떠올리면 되는지"를 기준으로 카테고리를 나눠 정리했습니다.

## 세션을 관리할 때

대화가 길어져 느려졌거나, 하던 작업을 잠시 미뤄두고 다른 걸 하고 싶을 때 쓰는 명령어들입니다.

| 명령어 | 언제 쓰는가 |
|---|---|
| `/clear` | 지금 작업과 무관한 새 주제를 시작할 때. 이전 대화는 사라지지 않고 `/resume`으로 다시 접근 가능 |
| `/compact [지시사항]` | 같은 작업을 계속 이어가되 컨텍스트가 꽉 찼을 때. 대화를 요약해서 여유 공간을 확보 |
| `/resume` | 어제 하던 세션을 이어서 하고 싶을 때. 세션 선택기가 뜨고 이름/프로젝트로 필터링 가능 |
| `/rewind` (별칭 `/undo`) | 방금 한 수정이 잘못됐다고 판단될 때. 코드/대화를 특정 시점으로 되돌림 |
| `/branch [이름]` | 지금까지의 대화 맥락은 유지한 채, 다른 방향으로도 한번 시도해보고 싶을 때 |

이 중 가장 헷갈리기 쉬운 건 `/clear`와 `/compact`의 차이입니다. `/clear`는 "완전히 새 주제로 넘어간다"는 뜻이고, `/compact`는 "같은 작업을 계속하되 지금까지의 기록을 압축해서 여유를 만든다"는 뜻입니다. 예를 들어 리팩토링 작업 하나를 붙잡고 몇 시간째 대화가 이어지고 있다면 `/compact`가 맞고, 리팩토링이 끝나고 이제 문서 작업을 새로 시작한다면 `/clear`가 맞습니다.

## 지금 상태를 확인하고 싶을 때

"컨텍스트를 얼마나 썼지", "오늘 토큰을 얼마나 썼지" 같은 궁금증이 생겼을 때 쓰는 명령어입니다.

| 명령어 | 언제 쓰는가 |
|---|---|
| `/context` | 컨텍스트 윈도우가 얼마나 찼는지 시각적으로 확인하고 싶을 때. `/compact` 타이밍 판단에 도움 |
| `/usage` (별칭 `/cost`, `/stats`) | 토큰 사용량, 비용, 사용 한도를 확인하고 싶을 때 |
| `/status` | 현재 로그인 계정, 버전, 연결 상태를 빠르게 확인하고 싶을 때 |

## 설정을 바꿀 때

세션을 끊지 않고 모델이나 환경을 바꾸고 싶을 때 쓰는 명령어입니다.

| 명령어 | 언제 쓰는가 |
|---|---|
| `/model` | 지금 하려는 작업 난이도에 맞게 모델을 바꾸고 싶을 때. 예: 간단한 수정은 가벼운 모델로, 복잡한 설계는 무거운 모델로 |
| `/effort [수준]` | 같은 모델이지만 추론에 더 공을 들이게(또는 덜 들이게) 하고 싶을 때 |
| `/config` | 테마, 출력 스타일, 에디터 모드 같은 환경 설정을 바꾸고 싶을 때 |
| `/permissions` | 특정 도구나 명령을 자동 허용/차단하도록 권한 규칙을 조정하고 싶을 때 |

`/config`는 `/config key=value` 형태로 인터페이스를 열지 않고도 바로 값을 지정할 수 있어서, 반복적으로 같은 설정을 바꾸는 상황이라면 이 방식이 더 빠릅니다.

## 개발 작업을 도와줄 때

코드 리뷰, 계획 수립, 변경사항 확인처럼 실제 개발 흐름에서 쓰는 명령어들입니다.

| 명령어 | 언제 쓰는가 |
|---|---|
| `/plan [설명]` | 큰 작업을 시작하기 전에 먼저 분석/설계만 하고 싶을 때. 읽기 전용이라 파일을 건드리지 않음 |
| `/init` | 새 프로젝트에 처음 들어왔을 때. 프로젝트를 스캔해서 `CLAUDE.md` 초안을 만들어줌 |
| `/memory` | `CLAUDE.md` 내용을 바로 편집하고 싶을 때 |
| `/diff` | 지금까지 어떤 파일이 바뀌었는지 턴별로 훑어보고 싶을 때 |
| `/code-review [노력수준]` (별칭 `/review`) | 지금까지의 변경사항에서 버그가 없는지 검토받고 싶을 때. 노력 수준(`low`~`max`)에 따라 검토 범위가 달라짐 |
| `/security-review` | 보안 관점에서 변경사항을 점검받고 싶을 때 |

예를 들어 데이터베이스 마이그레이션 스크립트를 새로 작성하는 작업이라면, 시작 전에 `/plan`으로 접근 방식을 먼저 점검하고, 작성이 끝난 뒤에는 `/code-review`로 스키마 변경이 안전한지 검토받는 흐름이 자연스럽습니다.

## 기타 유틸리티

설치 문제를 진단하거나, 대화를 내보내거나, 백그라운드 작업을 관리할 때 쓰는 명령어입니다.

| 명령어 | 언제 쓰는가 |
|---|---|
| `/doctor` (별칭 `/checkup`) | Claude Code가 이상하게 동작하거나, 설치/설정에 문제가 있는지 의심될 때 |
| `/export [파일명]` | 지금 대화 내용을 동료에게 공유하거나 기록으로 남기고 싶을 때 |
| `/tasks` (별칭 `/bashes`) | 백그라운드로 돌아가고 있는 작업 목록을 확인하고 싶을 때 |
| `/background` (별칭 `/bg`) | 지금 하던 세션을 백그라운드로 넘기고 터미널을 비우고 싶을 때 |
| `/todos` | 현재 세션이 추적 중인 TODO 목록을 보고 싶을 때 |
| `/feedback` (별칭 `/bug`) | 버그를 신고하거나 피드백을 보내고 싶을 때 |

## 번들 스킬 계열 명령어

일부 슬래시 명령어는 단순 설정 변경이 아니라, 내부적으로 여러 에이전트를 병렬로 오케스트레이션하는 "번들 스킬"을 호출합니다. 일반 명령어와 달리 작업을 스스로 분해해서 코드베이스에 맞게 동작합니다.

| 명령어 | 언제 쓰는가 |
|---|---|
| `/code-review ultra [PR번호]` | 로컬 리뷰보다 더 깊이 있는 검토가 필요할 때. 클라우드에서 여러 에이전트가 병렬로 분석 |
| `/batch <지시사항>` | 코드베이스 전반에 걸친 대규모 반복 수정이 필요할 때. 계획 수립부터 PR 생성까지 자동화 |
| `/run` / `/verify` | 테스트 통과 여부만으로는 불안하고, 실제로 앱을 빌드/구동해서 눈으로 확인하고 싶을 때 |

이 계열 명령어들은 실행 시간이 길고 여러 서브에이전트를 소모하므로, 간단한 확인이 필요한 상황이라면 `/code-review`(기본), 정말 꼼꼼한 검토가 필요한 상황이라면 `/code-review ultra`처럼 상황에 맞게 강도를 조절하는 것이 좋습니다.

## 퀵 입력 접두사

`/` 외에도 입력창 맨 앞에 특정 문자를 붙이면 즉시 다른 모드로 전환됩니다.

| 접두사 | 의미 | 예시 |
|---|---|---|
| `/` | 명령어 호출 | `/compact`, `/model` |
| `!` | Bash 모드 — 셸 명령을 바로 실행 | `!npm run build`, `!git log -5` |
| `@` | 파일 경로 멘션 — 자동완성 지원 | `@src/server.ts 이 파일 구조 설명해줘` |

예를 들어 지금 브랜치 상태가 궁금하면 굳이 모델에게 "git status 실행해줘"라고 말할 필요 없이 `!git status`를 바로 입력하면 됩니다. 반대로 특정 파일을 두고 대화하고 싶다면 `@` 뒤에 경로를 붙여 바로 지목할 수 있습니다.

## MCP 서버가 제공하는 프롬프트

MCP(Model Context Protocol) 서버를 연결하면, 그 서버가 등록해둔 프롬프트도 슬래시 명령어처럼 호출할 수 있습니다. 형식은 `/mcp__<서버이름>__<프롬프트이름>`입니다.

```
/mcp__github__list_prs
/mcp__jira__create_issue "로그인 버그" high
```

이런 명령어는 내장 명령어 목록에는 없고, 연결한 MCP 서버가 어떤 프롬프트를 제공하느냐에 따라 동적으로 늘어납니다.

## 정리

Claude Code의 슬래시 명령어는 크게 세션 관리, 상태 확인, 설정 변경, 개발 보조, 유틸리티, 그리고 여러 에이전트를 오케스트레이션하는 번들 스킬로 나눌 수 있습니다. 전부 외우기보다는, "지금 컨텍스트가 꽉 찼나(`/compact`)", "이 작업은 계획부터 세워야 하나(`/plan`)", "변경사항을 검토받아야 하나(`/code-review`)"처럼 지금 상황에 맞는 카테고리를 먼저 떠올리고, 세부 명령어는 `/`를 입력해 필터링하며 찾는 것이 실용적입니다. 여기에 `!`(Bash), `@`(파일 멘션) 같은 퀵 입력 접두사까지 함께 쓰면 대화 흐름을 끊지 않고도 필요한 조작을 빠르게 처리할 수 있습니다.
