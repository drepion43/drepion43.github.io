## 들어가며

앞선 글에서 [설치 방법]({% post_url 2026-07-27-ClaudeCode_Install %})과 [에이전트 루프의 동작 원리]({% post_url 2026-07-28-ClaudeCode_동작원리 %})를 다뤘습니다. 이번 글에서는 실제로 세션 안에서 생산성을 높여주는 **슬래시 커맨드(Slash Command)** 를 정리하겠습니다. Claude Code는 대화형 세션 도중 `/`로 시작하는 명령어를 입력하면, 모델에게 자연어로 요청하는 대신 정해진 동작을 즉시 실행합니다. 크게 **기본 제공 커맨드**와 사용자가 직접 정의하는 **커스텀 커맨드**로 나눌 수 있습니다.

## 기본 제공 슬래시 커맨드

Claude Code를 설치하면 별도 설정 없이 바로 쓸 수 있는 커맨드들입니다. 역할별로 묶어서 정리하면 다음과 같습니다.

### 세션/대화 관리

- `/help` — 사용 가능한 커맨드 목록과 간단한 설명을 보여줍니다.
- `/clear` — 현재 대화 히스토리를 초기화합니다. 새로운 작업으로 넘어갈 때 이전 맥락이 방해가 되지 않도록 할 때 유용합니다.
- `/compact` — 지금까지의 대화를 요약해서 컨텍스트를 압축합니다. 긴 세션에서 토큰 한도에 가까워졌을 때 사용합니다.
- `/resume` — 이전에 진행하던 세션을 다시 불러옵니다.

### 모델/환경 설정

- `/model` — 사용할 모델을 전환합니다(예: 빠른 응답이 필요한 작업과 깊은 추론이 필요한 작업을 구분해서 모델을 바꿀 수 있습니다).
- `/config` — 테마, 알림 등 클라이언트 환경설정을 확인/변경합니다.
- `/permissions` — 어떤 도구(파일 수정, 셸 명령 실행 등)를 자동으로 허용할지, 매번 승인받을지를 설정합니다.
- `/add-dir` — 현재 세션이 접근할 수 있는 작업 디렉터리를 추가합니다.

### 프로젝트 초기화/진단

- `/init` — 현재 프로젝트를 스캔해서 `CLAUDE.md` 초안을 생성합니다. 프로젝트 구조, 컨벤션을 모델이 이해하기 쉽도록 정리해줍니다.
- `/doctor` — 설치 상태, 권한, 연결 상태 등을 점검해서 문제를 진단합니다.
- `/cost` — 현재 세션에서 사용한 토큰/비용을 확인합니다.

### 코드 작업 보조

- `/review` — 현재 변경 사항(diff)에 대해 코드 리뷰를 요청합니다.
- `/pr_comments` — 연결된 GitHub PR의 코멘트를 가져와 반영할 작업으로 정리합니다.
- `/bug` — 버그 리포트를 작성해 Anthropic에 제출할 수 있게 돕습니다.

### 확장 기능 관리

- `/mcp` — MCP(Model Context Protocol) 서버 연결 상태를 확인하고 관리합니다. 외부 도구(DB, 사내 API 등)를 Claude Code에 연결할 때 사용합니다.
- `/agents` — 서브에이전트(특정 역할에 특화된 보조 에이전트) 설정을 확인/관리합니다.
- `/hooks` — 특정 이벤트(도구 호출 전/후 등)에 실행할 훅 스크립트를 설정합니다.

기본 커맨드는 Claude Code 버전이 올라가면서 계속 추가되기 때문에, 정확한 최신 목록은 세션에서 직접 `/help`를 입력해 확인하는 것이 가장 정확합니다.

## 커스텀 커맨드란

기본 커맨드만으로는 팀/프로젝트마다 반복되는 작업(예: "테스트 작성 규칙에 맞춰 테스트 추가", "커밋 메시지 컨벤션에 맞춰 커밋")을 매번 길게 설명해야 합니다. 커스텀 커맨드는 이런 반복 프롬프트를 **재사용 가능한 나만의 슬래시 커맨드**로 등록하는 기능입니다.

### 저장 위치

커스텀 커맨드는 마크다운 파일 하나가 곧 커맨드 하나입니다. 저장 위치에 따라 적용 범위가 다릅니다.

- **프로젝트 커맨드**: `.claude/commands/` 아래에 저장하며, 해당 저장소를 여는 모든 사람에게 공유됩니다(git으로 커밋하면 팀원 전체가 사용 가능).
- **개인 커맨드**: 홈 디렉터리의 `~/.claude/commands/` 아래에 저장하며, 사용하는 모든 프로젝트에서 나만 사용할 수 있습니다.

파일 이름이 곧 커맨드 이름이 됩니다. 예를 들어 `.claude/commands/blog-post.md` 파일을 만들면 세션에서 `/blog-post`로 호출할 수 있습니다. 이 블로그 저장소의 `/blog-post` 커맨드가 바로 이 방식으로 등록되어 있습니다.

### 기본 구조

```markdown
---
description: 새 블로그 포스트를 작성하고 로컬에 커밋한다
---

다음 제목으로 새 블로그 글을 작성해줘: $ARGUMENTS

1. 카테고리를 정하고
2. 중복 여부를 확인하고
3. 본문을 작성한 뒤
4. 로컬에 커밋해줘 (push는 하지 마)
```

- **frontmatter**: `description`(커맨드 목록에 보여줄 설명), `allowed-tools`(이 커맨드 실행 중 자동으로 허용할 도구 범위) 등을 지정할 수 있습니다.
- **본문**: 실제로 모델에게 전달될 프롬프트입니다. 커맨드를 호출하면 이 내용이 그대로(또는 인자가 채워진 채로) 대화에 주입됩니다.
- **`$ARGUMENTS`**: 커맨드 호출 시 뒤에 붙인 텍스트가 이 자리에 그대로 치환됩니다. 예를 들어 `/blog-post "제목" <url>`이라고 입력하면 `$ARGUMENTS`에는 `"제목" <url>`이 들어갑니다.

### 네임스페이싱

`.claude/commands/` 아래에 하위 디렉터리를 만들면 커맨드 이름에 네임스페이스가 붙습니다. 예를 들어 `.claude/commands/git/commit.md`는 `/git:commit`처럼 호출됩니다. 커맨드 수가 많아지는 프로젝트에서 카테고리별로 정리할 때 유용합니다.

## 기본 커맨드 vs 커스텀 커맨드, 언제 무엇을 쓸까

| 구분 | 기본 커맨드 | 커스텀 커맨드 |
|---|---|---|
| 목적 | Claude Code 자체의 범용 기능 제어 | 팀/프로젝트 특화 워크플로우 자동화 |
| 예시 | `/clear`, `/model`, `/mcp` | `/blog-post`, `/deploy-staging`, `/review-checklist` |
| 관리 주체 | Anthropic이 클라이언트에 내장 | 사용자/팀이 마크다운 파일로 직접 정의 |
| 공유 범위 | 모든 사용자 동일 | 저장 위치(`project` vs `personal`)에 따라 결정 |

정리하면, 기본 커맨드는 세션·모델·권한 같은 **도구 자체의 동작**을 제어하는 용도이고, 커스텀 커맨드는 "우리 팀은 항상 이렇게 작업한다"는 **반복 작업의 절차**를 코드처럼 저장해두는 용도입니다. 실제로 프로젝트를 진행하다 보면 자주 쓰는 프롬프트 패턴이 생기기 마련인데, 이를 매번 새로 타이핑하는 대신 커스텀 커맨드로 등록해두면 팀 전체의 작업 방식을 일관되게 유지할 수 있습니다.

## 정리

- Claude Code의 기본 슬래시 커맨드는 세션 관리, 모델/환경 설정, 프로젝트 진단, 코드 작업 보조, 확장 기능 관리 등 도구 자체를 다루는 범용 기능을 제공합니다.
- 커스텀 커맨드는 `.claude/commands/`(프로젝트) 또는 `~/.claude/commands/`(개인)에 마크다운 파일로 정의하며, `$ARGUMENTS`로 인자를 받아 반복되는 프롬프트를 재사용 가능한 커맨드로 만들어줍니다.
- 정확한 최신 커맨드 목록은 버전마다 달라질 수 있으므로, 세션 안에서 `/help`로 직접 확인하는 습관을 들이는 것이 좋습니다.
